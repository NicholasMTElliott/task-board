### Migration Tooling
- Flyway via Docker (`redgate/flyway`) for SQL-first schema migrations
- Scripts in `db/migrations`, applied via `scripts/migrate.ps1`
- Migration chain: V1 (processed_events) → V2 (pgmq_core) → V3 (events_queue) → V4 (card_state) → V5 (run_log) → V6 (run_log step_name) → V7 (pgmq_pings_queue) → V8 (card_state_claimed_at) → V9 (agent_run) → V10 (step_result) → V11 (drop_run_log) → V12 (metrics: estimate column, started_at indexes, SQL views) → V13 (session timing: session_startup_ms on agent_run, session_exec_ms on step_result) → V14 (failure_reason: failure_reason TEXT NULL + CHECK constraint on agent_run; v_run_metrics updated to use failure_reason = 'RATE_LIMIT') → V15 (multi-tenant: drop & recreate `agent_run`, `step_result`, `card_state`, `processed_events` with `tenant_id` as leading PK column, all indexes lead with `tenant_id`, no data preserved) → V16 (recreate `v_run_metrics`, `v_step_duration`, `v_card_metrics`, `v_card_rework` projecting `tenant_id`) → V17 (candidate-group columns on `step_result`: `provider NOT NULL` backfilled, `candidate_group_id UUID NULL`, `candidate_index INT NULL`, `selected BOOL NULL`, `quality_score NUMERIC(4,2) NULL`, `evaluator_reasoning TEXT NULL`, partial index on `(tenant_id, candidate_group_id) WHERE candidate_group_id IS NOT NULL`, paired CHECK constraint on `(candidate_group_id, candidate_index)`) → V18 (recreate `v_step_duration` with candidate columns; new `v_candidate_outcomes` and `v_provider_role_metrics` views aggregated by `(role, provider)`) → V19 (partial UNIQUE index `uq_step_result_candidate_slot ON (tenant_id, candidate_group_id, candidate_index) WHERE candidate_group_id IS NOT NULL` so a duplicate-candidate-row bug fails loudly at the DB instead of producing silently-wrong metrics)

- ✅ Multi-agent candidate evaluation (`CandidateExecutor`, opt-in per step). `WorkflowStep` extended with `Candidates` (list of `CandidateOverride { Provider, Model?, ProviderParams? }`) + `Evaluator` (`EvaluatorConfig { Role, TaskPrompt(File)?, Scoring }` with `EvaluatorScoring.WinnerWithScores | WinnerOnly`). When set, the runtime spawns N candidate worktrees off canonical HEAD, runs each provider in parallel, then invokes the evaluator role to pick a `winner_index` + 0–10 `scores`. Winner is promoted via `git reset --hard`; losers are torn down. Per-(role, provider) wins/scores/duration recorded in V17-widened `step_result` (new columns: `provider NOT NULL` backfilled to `claude-cli`, `candidate_group_id UUID NULL`, `candidate_index INT NULL`, `selected BOOL NULL`, `quality_score NUMERIC(4,2) NULL`, `evaluator_reasoning TEXT NULL` + paired CHECK constraint). V18 recreates `v_step_duration` with the new columns and adds `v_candidate_outcomes` + `v_provider_role_metrics` (aggregated wins/win_rate/avg_score/avg_duration by `(role, provider)`). `IMetricsStore.GetProviderRoleMetricsAsync` and `GetCandidateHeadToHeadAsync` (alphabetical-pair self-join, ties counted as "neither selected") feed two new MetricsRunner output sections (suppressed when no candidate data exists yet) and two Grafana bargauge panels. Validator (`WorkflowConfigValidator.Validate`) errors on: `candidates` without `evaluator` (and vice versa), empty provider on a candidate, evaluator role missing from `Roles`, evaluator with neither `taskPrompt` nor `taskPromptFile`. **Previously rejected, now allowed** (the rejections were over-conservative): unlimited candidate count (was capped at 4 — eval-prompt size is the user's call), duplicate providers per group (legitimate for same-provider model A/B like Opus vs Sonnet on Claude, also for variance-measurement runs), `gitBehavior: discard` (now supported via file-based winner promotion). Verdict parser (`CandidateExecutor.ParseEvaluatorVerdict`) accepts JSON in three shapes — fenced `\`\`\`json`, whole-document, last balanced `{...}` with `winner_index` — and rejects out-of-range or negative `winner_index` rather than promoting nothing. **Score sanitisation:** the parser drops scores outside `[0, 10]` to null (keeps reasoning) so out-of-contract values don't pollute `avg_quality_score` in metrics; **dedupes duplicate `index` entries** in `scores[]` with last-write-wins semantics so a draft+revise output doesn't double-count. **All-failed merged outcome** prefers `NEEDS_INFO` over `ERROR`: when every candidate returns non-COMPLETE, the step's surfaced outcome is `NEEDS_INFO` if any candidate asked a question (recoverable — card moves to Questions for human answer), otherwise `ERROR`. Candidate declaration order does NOT determine routing. **Phases 3–5 wrapped in `try/finally`**: verdict parsing, persistence, winner promotion, and per-candidate comment posting run inside a finally block that always deletes the evaluator's inline-system-prompt temp file (`$TMP/aiboard-evaluator-{guid}.md`), so unexpected exceptions in any of those phases don't orphan files in `/tmp`. Evaluator step is recorded as a regular `step_result` row with name suffix `:evaluator`, NOT carrying `candidate_group_id` (so `WHERE candidate_group_id IS NOT NULL` filters in the metrics views never count it as a candidate). Candidate branch naming uses a **separate** `aiboard-cand/{cardId}-{groupShort}-{index}-{provider}` prefix — NOT nested under the canonical branch path — because nested git worktrees fail. Candidates run as short-lived processes (no session reuse — each candidate has a different worktree mount). Default evaluator role in `workflow.github.json` is `evaluator` → `claude-opus-4-6`; system prompt at `prompts/evaluator.md`; per-step-type task prompts at `prompts/evaluator/code_review_candidates.md` + `gate_check_candidates.md`. **V19 partial UNIQUE index** (`uq_step_result_candidate_slot ON (tenant_id, candidate_group_id, candidate_index) WHERE candidate_group_id IS NOT NULL`) is exercised by `PgRunStoreCandidateUniqueIndexTests`, which connects to the local Postgres from `docker-compose.yml` (override via `TASKBOARD_TEST_PG_CONNECTION` env var; test silently skips if the DB is unreachable so other suites still run). The test inserts a candidate row, then attempts a second row with the same `(tenant, group, index)` but a different `step_name` (bypassing the run-id+step-name `ON CONFLICT` clause), and asserts the V19 UNIQUE constraint fires with SQLSTATE `23505`.
- ✅ Discard-mode candidate evaluation: `CandidateExecutor` now supports `gitBehavior: discard` states (design, tasking) by switching the winner-promotion mechanism from `git reset --hard {winner-branch}` (commit modes) to file copy. `PromoteDiscardWinnerArtifacts(winnerWorktree, canonicalWorktree)` clears the canonical's `.aiboard/{tasks,updates}/` then copies the winner's contents in (mirror semantics — a winner that *removed* a file is reflected). All candidate branches (winner included) are torn down afterward; canonical's git state is unchanged. The evaluator prompt also forks: commit modes get `git diff` per candidate (the actual code change); discard modes get the candidate's `.aiboard/tasks/{cardId}.md` content (the design / card body) + listing of `.aiboard/updates/*.md` files (since `.aiboard/` is gitignored, `git diff` is empty for discard candidates and would give the evaluator nothing to compare on). `IsDiscardMode(string?)` is the case-insensitive helper that gates both branches. `comments/` and `images/` are deliberately NOT promoted because they're inputs (refreshed from the board before each run); copying stale candidate copies over canonical inputs would be wrong. Validator no longer rejects candidates on `discard` states; candidate count is uncapped (was 4); duplicate-provider rejection removed (legitimate use cases: same-provider model A/B like Opus vs Sonnet on Claude, and variance-measurement runs of identical agent twice). Tested by `DiscardMode_WinnerArtifactsCopied_NoGitCommitsOnCanonical` in `CandidateExecutorFlowTests`.
- ✅ Claude-CLI-on-Qwen executor (`DockerClaudeQwenAgentExecutor`, provider key `docker-claude-qwen`): third Qwen-target executor sitting alongside `docker-opencode`. Reuses `aiboard-agent-sandbox:latest` (the existing Claude CLI image) — the Qwen redirect is purely runtime env-var work, no separate sandbox image.
